# 系统管理与环境依赖

点击左下角 **系统管理**（设置图标），弹窗内含三个页签：**环境管理** / **环境依赖** / **关于**。

---

## 1. 环境管理

后端是一个本地 Flask 服务（默认端口 `18081`），需要一个装好依赖的 Python 环境。

| 项 | 说明 |
|---|---|
| 当前环境 | 显示正在使用的环境名称/路径与 Python 版本 |
| 可用环境 | 列出扫描到的 Conda 环境，标记依赖是否齐全 |
| 重新扫描 | 重新枚举本机 Conda 环境 |
| 重新配置 | 停止后端并回到首次启动向导，重新选择环境 |

- 首次启动会进入 **首启配置向导**：可选「使用 Conda 环境」（自动扫描，推荐）或「手动指定 Python」（填 `python.exe` / `python` 完整路径）。
- 环境中需要 Flask、Pillow 等 `requirements.txt` 依赖；标记 `✓` 表示齐全，缺依赖会明确列出包名。
- 切换环境后后端会自动使用新解释器重启。

依赖安装（在目标环境中执行）：

```bash
pip install -r requirements.txt
# AI 自动标注 / 智能抽帧还需要
pip install ultralytics
```

## 2. 环境依赖

**系统管理 → 环境依赖** 列出客户端运行所需的全部依赖，并可导出为 Conda 环境文件。

| 元素 | 说明 |
|---|---|
| 必需依赖 | 后端运行所需（Flask、Pillow、numpy、opencv-python 等），标「已安装 / 未安装」 |
| AI 依赖 | `ultralytics`、`torch`、`torchvision`，由「包含 AI 依赖」开关控制是否纳入 |
| Python 版本 | 顶部显示所需的 3.10+ 与当前后端实际版本 |
| 导出 Easy Conda YAML | 保存为 `environment.yml`，可直接在 Easy Conda 中「导入 environment.yml」一键建环境 |

导出的 `environment.yml` 结构大致为：

```yaml
name: easy-dataset
channels:
  - conda-forge
  - defaults
dependencies:
  - python=3.10
  - ffmpeg              # AI 抽帧的分段并行依赖
  - pip
  - pip:
      - -r requirements.txt
      - ultralytics     # 勾选 AI 依赖时才有
```

用法建议：

1. 在新机器上导出 `environment.yml`；
2. 用 Easy Conda（或 `conda env create -f environment.yml`）建环境；
3. 回到客户端 → 系统管理 → 环境管理 → 重新扫描 → 选中新环境。

依赖清单来自组件内的 `requirements.txt`，与实际安装内容一致，不会出现"清单和代码不同步"。

## 3. 关于

| 项 | 说明 |
|---|---|
| 版本 | 当前客户端版本（如 v1.0.0） |
| 检查更新 | 读取公开发布清单，有新版本时提示下载 |
| 亮 / 暗色 | 切换界面主题 |
| 产品主页 / 代码仓库 / 技术支持 | 外部链接，用系统浏览器打开 |
| 许可 | GPL-3.0，按「现状」提供 |

更新说明：

- 更新检查只读公开的版本清单，不上传任何数据。
- 安装包升级后，客户端会在启动时把内置后端资源同步到 **按版本号隔离的运行目录**，不会与旧进程冲突；首次启动会稍慢几秒属正常现象。

## 4. 语言与界面

- 支持简体中文 / English / 日本語，在界面内切换后立即生效。
- 语言、主题、上次使用的路径都保存在本地，不上传。

---

## 5. 后端进程

- 客户端启动时会自动拉起后端；退出客户端时会同时结束后端（Windows 下按进程树终止，不会残留黑窗口）。
- 若后端异常退出，界面顶部会给出提示，可在系统管理里重新启动或重新配置。
- 后端仅监听 `127.0.0.1`，不对外网开放；需要额外鉴权时可在运行目录放 `.env` 设置 `API_TOKEN`。
